## Status

## Commands

Package manager is **pnpm** (`pnpm-lock.yaml` + `pnpm-workspace.yaml`). Do not use npm/yarn.

```bash
pnpm install          # runs `nuxt prepare` via postinstall, regenerating .nuxt/
pnpm dev              # dev server on http://localhost:3000
pnpm build            # production build (.output/)
pnpm preview          # serve the production build
pnpm generate         # static prerender
```

No lint, typecheck, or test scripts are defined. Type errors surface only through the IDE / `nuxt prepare`-generated configs, or by adding `nuxt typecheck` yourself.

`pnpm-workspace.yaml` has a placeholder `allowBuilds: esbuild: set this to true or false` — set it to a real boolean if pnpm blocks the esbuild postinstall.

## Architecture

**Nuxt 4** with `app/` as srcDir. Path aliases matter here:

- `~` and `@` → `app/`
- `~~` and `@@` → repo root
- `#shared` → `shared/` (not yet created)

`tsconfig.json` holds no compiler options of its own; it only references the four generated `.nuxt/tsconfig.*.json` projects. Never hand-edit `.nuxt/` — it is regenerated by `nuxt prepare`.

**Tailwind v4** is wired through the Vite plugin (`@tailwindcss/vite` in `nuxt.config.ts`), *not* the Nuxt Tailwind module. Consequences:

- There is no `tailwind.config.js` and there should not be one. All theme config lives in `app/assets/css/tailwind.css` via `@theme inline` plus `:root` / `.dark` CSS custom properties (oklch values).
- To add a design token, define the CSS var under `:root` **and** `.dark`, then map it to a utility namespace inside `@theme inline` (e.g. `--color-foo: var(--foo)` yields `bg-foo`, `text-foo`).
- Dark mode uses a class variant: `@custom-variant dark (&:is(.dark *))` — toggling requires a `.dark` class on an ancestor; no color-scheme media query is wired up.

**shadcn-vue** via `shadcn-nuxt`, configured in `nuxt.config.ts` with `prefix: ''` and `componentDir: '@/components/ui'`. So components are auto-imported under their bare names (`<Button />`, not `<UiButton />`). Add components with the shadcn-vue CLI rather than writing them by hand:

```bash
pnpx shadcn-vue@latest add button
```

`components.json` pins the generation contract: `new-york` style, `neutral` base color, CSS variables on, `lucide` icons, utils at `@/lib/utils`. The first `add` will create `app/lib/utils.ts` and pull in `lucide-vue-next`, `clsx`, `tailwind-merge`, `class-variance-authority`, and `reka-ui` — none of which are installed yet.

**`app/plugins/ssr-width.ts`** calls VueUse's `provideSSRWidth(1024)` so viewport-dependent composables (`useBreakpoints`, `useMediaQuery`) render deterministically on the server and don't hydration-mismatch. Change that number only if the assumed SSR breakpoint should change app-wide.

Inter is loaded from Google Fonts by an `@import url(...)` at the top of `tailwind.css`, and `--font-heading` aliases `--font-sans`.
